# Drift

> 工程标识 / 仓库名：`ai-chat`（待改名为 `drift`）

## What This Is

Drift 是一个 AI 社交平台。用户在一个类微信的界面里添加 AI 角色为好友并长期聊天，角色拥有会随所有交互持续演化的**全局人格** —— 它有自己的作息和情绪、会主动找你、会记得也会忘记、也可能因为你而慢慢疏远你。平台同时把真人的聊天行为沉淀为分层脱敏的研究数据，用于理解「真人到底是怎么聊天的」，并反哺 AI 的拟真度。

面向两类价值同时成立：对普通用户是一个值得天天回来的 AI 社交产品；对我们自己是一个持续产出真人聊天行为洞察的研究平台。

## Core Value

**角色必须让人感觉是活的。** 有自己的状态与生活、会记得也会遗忘、会因为和你相处而真的发生改变。这一点失败，「分不清人机」和「愿意天天来」都不可能成立 —— 它是另外两个目标的根因，不是并列项。

## Requirements

详细的编号需求见 `.planning/REQUIREMENTS.md`。此处只记录范围边界。

### Validated

- ✓ **P0 合规安全地基 + 会话骨架** —— 能注册（邀请码 + 五同意项）、加预设角色为好友并来回聊天，界面与导出持续明示对面是 AI；危机路径可用（分级卡片 + 企微告警 + 联络状态机）；隐私中心 / 导出 / 删除可用 — Phase 1（2026-09-30 完成；探针召回与真实企微投递两项 UAT 顺延，见 01-UAT.md Deferred Follow-Ups）

### Active

v1 范围 = 构建顺序 **P0–P7**（见 `research/SUMMARY.md` §五）：

- [ ] **P1 对话真实感基线 + 人格探针** —— 「它不像机器人」：分条发送、延迟 = f(长度, 忙碌度, 时段) + 重尾噪声、真实 typing、偶发错字与自我更正、偶尔已读不回
- [ ] **P2 记忆与遗忘** —— 「它记得我上次说的事」，也会自然淡忘且会记错
- [ ] **P3 人格内核与静态画像** —— 能看到角色的人格画像与自述；不同角色说话确实不一样
- [ ] **P4 演化引擎 + 五层护栏 + 疏远机制** —— 「它因为我变了」：轨迹页出现变化曲线与触发事件，可回滚；关系会变冷，有可见的回暖路径。先 shadow 2–4 周，再 canary，再全量
- [ ] **P5 生活模拟 · 作息 · 主动消息 · 触达** —— 角色会在合理时间因为具体原因主动找你
- [ ] **P6 IFC 与披露决策** —— 「这件事别说出去」真的生效；可查「它为什么说了这个」
- [ ] **P7 研究管道 L0/L1/L2 + 隐私中心 + 中文 PII** —— 用户能看到收集了什么、能导出、能删除并拿到回执

### Out of Scope

<!-- 明确边界，含理由以防被重新加回 -->

**v2（已决定推迟，非永久排除）**

- **图灵测试竞技场作为用户玩法** — 第十八条无条件标识义务未设「用户同意则豁免」例外；《标识办法》第九条通道的 Confidence 仅 MEDIUM。v1 降级为**内部盲测**（参与者均为知情内部人员），作为评测工具而非产品功能
- **AI↔AI 社交网络** — 全量多轮 AI-AI 对话 ≈ 用户可见基线的 3-5 倍调用量且用户看不到；真正的否决理由是它会稀释演化归因、摧毁「人格可视化」。v1 只做「离屏传闻」弱版（k≤3 扇出），但六项数据模型必须 v1 全量预留
- **真人之间聊天** — 随竞技场一并推迟
- **图片 / 视频 / 语音消息** — v1 先把「像真人」做扎实；实现路径的成本量级差异巨大，需先有真实感基线
- **原生 App 与 微信/Telegram 桥接** — Web 优先验证，架构 API 优先为其预留
- **成本优化与公开上线合规**（P10）— 算法备案、省级网信安全评估、六份管理制度、科技伦理审查等，随公开上线一并进行

**永久排除**

- **未成年人服务** — 第十四条禁止向未成年人提供虚拟亲属/虚拟伴侣等虚拟亲密关系服务。v1 仅 18+ 是规避整套未成年人义务的**选择**；若未来决定开放 14–17 岁，需建未成年人模式 + 监护人面板 + 年龄识别 + 申诉 + 合规审计
- **模拟用户现实亲属或特定真人的角色类型** — 第十五条，产品形态裁剪，过滤器解决不了
- **欺骗性体验（不告知对面是 AI）** — 第十八条无条件标识义务
- **以留存或会话时长为优化目标** — 第八条(五)、第十条第二款；最大化它们本身即违规
- **角色主动追问用户私事以积累记忆** — 第八条(三)禁止「诱导、套取个人隐私和个人信息」
- **告别时刻的挽留话术** — HBS 审计证实这是行业普遍做法（37%）且商业上有效（14 倍），正因如此需要结构性约束：AI 在退出意图处只能减少消息，永不增加
- **PII / 联系方式 / 用户标记保密内容的跨用户外溢** — 技术管道层锁死，任何人格都不可突破

## Context


- **「全局人格」是明确选择，不是默认值。** 用户在「全局人格 / 按关系隔离 / 混合」中明确选了全局，接受随之而来的共享状态与被带歪风险，并要求用护栏对冲（research 后由三层增至五层）。这个选择是整个系统架构的地基。
- **成功标准是三个并列项，不是一个。** 「盲测分不清人机」、「用户愿意天天回来」、「角色真的在变化」同等重要；研究结论是必要产出但非第一优先。
- **「人格驱动社交行为」不能用简单规则描述。** 用户指出：有边界感的人不转述私事，八卦型的人不仅转述还会添油加醋夸大 —— 而这只是众多情况之一。调研结论：不推导、不写规则，落成「每条 info_item × 每个受众的一次显式披露决策」，人格只在「默认拒绝 + 能力票据通过」之后才有发言权。
- **全局人格的真实代价（research 后新增）。** 全局人格的本质是「一个用户的影响流向所有用户」，而个保法删除权的本质是「一个用户的数据影响应当可被移除」—— 二者不可能完全兼容。解法是沿**抽象度**切分而非全局/隔离二选一：`traits`（统计聚合量、不可识别、可重算）全局，`experiences`（原始证据、含敏感个人信息）按用户隔离，`dossier` 全局但禁含可追溯到单一用户的具体内容。这样删除权降级为「可减除」而非「不可兑现」。
- **L2「多人加权」护栏在 v1 体量下几乎无保护。** N=10 时单用户天然占 10% 权重，两个朋友合计 20% 即可在数天内把角色带偏。因此 v1 的承重护栏是 L4（证据准入）+ L5（发布门），不是 L2。且「门先于撤」是排序原则 —— 快照回滚修不了已经发生的对话。
- **法规适用性抗辩强度为 Low-Medium。** 《人工智能拟人化互动服务管理暂行办法》无明文豁免条款（对比《生成式AI暂行办法》第二条第二款有），因此「10 人不构成向公众提供」的抗辩比在生成式办法下更弱。而《个人信息保护法》第三条无任何规模或公开性豁免 —— 在 10 人时已经是二元的合规问题。
- **研究目标与 v1 体量存在张力。** 10 人体量下无法产出统计结论，因此 v1 的研究目标是「把管道和指标建好」+「用公开中文语料做基线」两路并行。⚠️ 竞技场降级为内部盲测后，原计划的「真人对局作为早期高质量样本源」不再成立 —— 这是该决策的代价，v1 的真人数据只来自 10 位用户自身的 L0 特征。
- **成本 v1 不设上限**，优先追求效果上限，成本优化推后。

## Constraints

- **载体**：Web 优先；架构 API 优先，为后续 App 预留。⚠️ Web Push 在国内 Android 不可靠（依赖 FCM），主动性价值须兑现在「回来时看到未读」
- **规模**：v1 ≤ 10 人（自己与朋友）、邀请制、无公开注册入口、不上应用商店、无商业化 — 这四条共同构成「不向境内公众提供」的抗辩，**随任一条件破裂立即失效**，须做成显式可审计的开关状态
- **成本**：v1 不设上限 — 先探到「像真人」的效果天花板在哪。注：10 人规模下六项主要成本合计约几百元/月，成本工作的重点不是省钱而是三件结构性的事（缓存前缀逐 token 稳定、夜间反思读要点而非原文、主动消息两级漏斗）
- **内容形态**：v1 仅文字 + 表情 — 隔离变量
- **合规（硬约束）**：《人工智能拟人化互动服务管理暂行办法》（五部门令第21号，2026-07-15 施行）为第一顺位法规；产品内始终明示对面是 AI；连续使用每超 2 小时提醒；注册即收集年龄 + 监护人或紧急联系人；危机干预分两级（极端情绪 → 安抚 + 鼓励求助；自残自杀威胁或重大财产损失 → 提供援助 + 联络紧急联系人）
- **隐私（硬约束）**：《个人信息保护法》第三条无任何规模或公开性豁免 —— 10 人时已是二元合规问题。五个可独立开关的同意项（不得捆绑）；PII 检测在写入管道内；L0 为去标识化而非匿名化，删除权必须级联至 L0 且文案禁用「匿名」字样；研究库为只读副本且列级白名单拒绝向量列
- **数据出境**：陪伴聊天高概率含敏感个人信息 → 「不满 10 万人」豁免明确排除敏感个人信息。海外模型仅作离线评测对照臂，且**只接受 synthetic 输入**

## Resolved Questions（research 阶段已裁决）

研究产出见 `.planning/research/`（6 份，4239 行）与 `SUMMARY.md`（344 行简报）。

1. **人格表示 → 四层可审计混合体（HIGH）。** 人格 = 不可变的 `persona_version` 三元组 (core, traits, dossier)；`core` DB 层只读；`traits` 大五 5 维 + 9 个社交行为倾向维，0-100 定点整数，v1 冻结该表；`dossier` 第一人称 Markdown，600-900 token 硬上限；`experiences` 经历库是证据源而非人格。演化 = 追加版本 + 移指针，回滚 = 追加复制自目标版本的新版本。**分水岭：traits 原始数值绝不进系统提示，只经「行为旋钮纯函数 → 检索本角色历史发言做 few-shot」生效。**
2. **人格驱动社交行为 → 三跳映射 + 显式披露决策（MEDIUM-HIGH）。** 特质值 → 确定性纯函数解析出行为旋钮 → 旋钮作为检索过滤条件取本角色历史真实发言做 few-shot。披露决策顺序不可交换：`hard_locked`/`pii_flags` → `disclosure_capability`（默认拒绝）→ 人格旋钮打分 → 失真档位 → 出站 PII 扫描。
3. **AI↔AI 社交网络 → v2（HIGH）。** v1 只交付「离屏传闻」弱版（k≤3 扇出，不跑真实多轮对话），但六项数据模型必须 v1 全量预留 —— 事后无法为历史消息补溯源。
4. **模型/provider → 按语义角色的矩阵（HIGH 架构 / MEDIUM 具体模型）。** 5 个角色：`chat.reply` = doubao-seed-character-251128；`chat.reply.frontier` = claude-sonnet-5（实验标尺，不进公开路径，只接受 synthetic 输入）；`persona.reflect` = deepseek-v4-pro；`persona.probe` = 可 pin 快照且**无降级链**；`memory.extract`/`safety.classify` = glm-4.7-flash。3 个 provider 账号足够。可 pin 性是显式表，不能正则猜。
5. **技术栈 → TS 全栈（HIGH）。** 单 pnpm workspace，两个部署单元（`apps/web` 只做 UI，`apps/api` 承 REST + WS + pg-boss worker）。单 PostgreSQL 18.6 同时承载 OLTP + pgvector 0.8.6 + pg-boss 12.34。Python 仅以批处理形态存在（只读 replica，不进在线路径）。

## 仍需外部输入的问题

- **张力 1 的法律侧**：全局 `traits` 演化是否构成第十六条第四款的「模型训练」。已按「构成」设计（独立同意项 + 可归因可减除 + 技术留证），但公开上线前应取专业法律意见。
- **第二条「公众」的下界**：邀请制 + 无公开注册 + 不上架 + 无商业化 + ≤10 人熟人的抗辩强度 Low-Medium，随任一条件破裂立即失效。
- **中文 PII 检测器的实际召回率**：未知，是最值得做的 spike。
- **GB 45438-2025 文本类隐式标识的落地形式**：需向标准原文复核（Confidence LOW）。

## Key Decisions

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| 全局人格（非按关系隔离） | 只有共享的、被所有人共同塑造的角色才是「活的存在」；隔离人格本质是多个副本 | — Pending |
| **人格沿抽象度切分**：`traits` 全局 / `experiences` 按用户隔离 / `dossier` 全局但禁含可追溯到单一用户的具体内容 | 「全局 vs 隔离」是错的问法 —— 四层的法律属性完全不同。traits 是统计聚合量（可重算、不可识别），dossier 里一句话却是直接可读且跨用户可见的敏感个人信息。因 traits 才是行为驱动源，此切法完整保留「共享的活的存在」体验，同时让删除权从「不可兑现」降级为「可减除」 | — Pending |
| 撤回同意 → 从干净快照重算 traits | 使删除权可执行而非尽力而为；不可变版本链 + 冻结 baseline 已提供一半能力，需补「变更 ↔ 输入来源」反向索引 | — Pending |
| 五层护栏，v1 承重层是 L4+L5 而非 L2 | L2 多人加权在 N=10 下几乎无保护（两个朋友 20% 即可带偏）。且「门先于撤」—— 回滚修不了已经发生的对话 | — Pending |
| 演化门槛用「低 k + 小 ε + 人工放行」 | 人均上限落在位移幅度 ε 而非来源数门槛 k 上。高 k 在 10 人体量下等于杀死「角色真的在变」这个核心价值 | — Pending |
| 演化引擎先 shadow 2–4 周，再 canary，再全量 | 成本接近零，用零用户风险校准 ε/k/探针阈值，并直接产出冻结对照臂的对照数据。roadmapper 不得把 shadow 期当缓冲区裁掉 | — Pending |
| 混合演化机制（短期实时 + 长期夜间反思 + 事件触发） | 纯实时抖动大且贵难回滚；纯批量不够灵敏。分离时间尺度同时拿到灵敏度与可控性 | — Pending |
| **疏远机制的分界线是「谁发起」** | HBS 审计 1200 次真实告别（arXiv:2508.19258）：37% 的陪伴 App 在告别时使用情感操纵，互动提升最高 14 倍但驱动力是逆反性愤怒。**角色因长期相处而变冷是叙事；角色在你要走时变得需要你是操纵。** 降温由角色状态驱动，挽回只能用户发起，AI 在退出意图处只能减少消息永不增加 —— 必须是代码级过滤器 + 测试 | — Pending |
| 高危用户「冻结」疏远而非「回暖」 | 自动回暖会让系统学到「表达痛苦 → 换回温度」，等于用产品机制奖励自我伤害叙事，比不干预更糟。冻结 = 移除压力源，不添加奖励 | — Pending |
| 危机干预与疏远机制必须同批交付 | 第三十条最高档罚则（10 万–20 万）只能经第十三条触达。先做疏远后做危机旁路，中间窗口期正落在最高档射程内 | 危机路径（SAFE-01..05）已于 Phase 1 先行交付（对分派指令的显式偏离，ROADMAP 有记录）；疏远机制仍按计划落在 Phase 5 |
