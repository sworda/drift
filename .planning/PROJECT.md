# Drift

> 工程标识 / 仓库名：`ai-chat`（待改名为 `drift`）

## What This Is

Drift 是一个 AI 社交平台。用户在一个类微信的界面里添加 AI 角色为好友并长期聊天，角色拥有会随所有交互持续演化的**全局人格** —— 它有自己的作息和情绪、会主动找你、会记得也会忘记、也可能因为你而慢慢疏远你。平台同时把真人的聊天行为沉淀为分层脱敏的研究数据，用于理解「真人到底是怎么聊天的」，并反哺 AI 的拟真度。

面向两类价值同时成立：对普通用户是一个值得天天回来的 AI 社交产品；对我们自己是一个持续产出真人聊天行为洞察的研究平台。

## Core Value

**角色必须让人感觉是活的。** 有自己的状态与生活、会记得也会遗忘、会因为和你相处而真的发生改变。这一点失败，「分不清人机」和「愿意天天来」都不可能成立 —— 它是另外两个目标的根因，不是并列项。

### Active

**聊天基础体验**
- [ ] 类微信的 Web 聊天界面：会话列表、消息流、未读、文字 + 表情
- [ ] 预设角色库（精选角色保证质量）+ 用户自建角色（进阶能力）
- [ ] 添加好友流程，从「陌生人」开始建立关系

**真实感系统**
- [ ] 拟真回复节奏：回复延迟、打字中、角色作息、偶尔已读不回
- [ ] 情绪与状态系统：角色有心情和忙碌度，会影响回复质量与态度
- [ ] 角色「生活」模拟：日程表与事件流，让主动发消息有明确来源而非随机骚扰
- [ ] AI 主动发起对话
- [ ] 站内未读 + 浏览器 Web Push 触达
- [ ] 长期记忆 + 遗忘曲线（记忆会衰减、会记错 —— 完美记忆是 AI 的破绽）
- [ ] 拒绝与疏远机制：关系可以变冷、变坏甚至断掉，有挽回路径但不保证成功

**人格演化引擎**
- [ ] 全局人格模型：一个角色只有一个人格，与所有用户的交互共同塑造它
- [ ] 混合演化机制：短期状态（心情/精力）实时变化；长期人格走「夜间反思」批量整合；重大事件（强情绪冲突、重要承诺、关系跃迁）可即时触发
- [ ] 三层人格护栏：核心价值观与安全边界锁死不可被用户改写 + 单用户影响力需多人交互趋势加权 + 定期人格快照可回滚
- [ ] 人格档案可视化：让用户看到「这个角色因为你发生了什么变化」的轨迹（不可见的进化等于没进化）

**研究与度量**
- [ ] 分层研究数据管道：L0 默认层只存脱敏行为特征（消息长度分布、回复间隔、标点与表情使用率、话题类别、主动发起率），不存原文
- [ ] L1 研究授权层：用户显式授权后保留原文，写入前 PII 脱敏，研究 ID 与账号 ID 分表映射且映射表单独加密
- [ ] L2 单次授权层：可被人工阅读与标注的样本，逐会话确认
- [ ] 隐私中心：可见「收集了什么」、一键导出、一键删除（级联到研究库，走删除队列）
- [ ] 图灵测试竞技场：随机匹配对手（AI 或真人），聊完猜身份 —— 同时提供人机指标度量场、早期真人对话数据源、增长玩法，并顺带落地真人之间聊天能力
- [ ] 真人聊天风格画像与指标看板
- [ ] 公开中文对话语料作为基线，与平台数据做对比分析

**平台能力**
- [ ] 多 provider 模型抽象层（可切换，避免被单一供应商锁定）

### Out of Scope

<!-- 明确边界，含理由以防被重新加回 -->

- **图片与视频消息** — v1 先把「像真人」这件事做扎实；素材库与实时生成的成本量级差异巨大，需要先有真实感基线再决定实现路径
- **语音消息** — 同上，归入 v2 一并评估
- **原生 App** — Web 优先验证，但架构 API 优先，为 App 阶段预留
- **微信 / Telegram bot 桥接** — 触达真实感最强，但留到 App 阶段再接第三方
- **欺骗性体验（不告知对面是 AI）** — 合规底线：产品内始终明示对面是 AI。「分不清人机」的度量只在独立盲测场景（竞技场）进行，该场景有单独知情同意
- **PII / 联系方式 / 用户标记保密内容的跨用户外溢** — 技术管道层强制锁死，任何人格都不可突破。人格只影响社交层面的表达倾向，不影响这条底线
- **公开上线与规模化运营** — v1 仅 10 人以内，并发与滥用防护不是当前问题

## Context

- **「全局人格」是明确选择，不是默认值。** 用户在「全局人格 / 按关系隔离 / 混合」中明确选了全局，接受随之而来的共享状态与被带歪风险，并要求用三层护栏对冲。这个选择是整个系统架构的地基。
- **成功标准是三个并列项，不是一个。** 「盲测分不清人机」、「用户愿意天天回来」、「角色真的在变化」同等重要；研究结论是必要产出但非第一优先。
- **「人格驱动社交行为」不能用简单规则描述。** 用户指出：有边界感的人不转述私事，八卦型的人不仅转述还会添油加醋夸大 —— 而这只是众多情况之一。整个「人格如何驱动社交行为」的建模方式是开放问题，需先调研再决策。
- **研究目标与 v1 体量存在张力。** 10 人体量下无法产出统计结论，因此 v1 的研究目标是「把管道和指标建好」+「用竞技场的真人对局补充高质量样本」+「用公开语料做基线」三路并行。
- **成本 v1 不设上限**，优先追求效果上限，成本优化推后。

## Constraints

- **载体**：Web 优先；架构 API 优先，为后续 App 预留 — 快速验证 + 不返工
- **规模**：v1 ≤ 10 人（自己与朋友）— 不为不存在的并发做设计
- **成本**：v1 不设上限 — 先探到「像真人」的效果天花板在哪
- **内容形态**：v1 仅文字 + 表情 — 隔离变量，避免多模态成本掩盖对话质量问题
- **合规（硬约束）**：产品内始终明示对面是 AI；盲测仅限独立实验场景且需单独知情同意
- **隐私（硬约束）**：三层授权分层存储；PII 检测在写入管道内而非事后；研究库为只读副本且不含联系方式；所有研究查询留审计日志

## Open Questions（交由 research 阶段）

按优先级排序 —— 第 1 项选错，后面全部要重做。

1. **人格该怎么被表示？** 候选：(A) 结构化向量（大五人格 + 自定义维度）— 可计算可演化可可视化，但易变成「演性格」而非「有性格」；(B) 自然语言人格档案（不断被重写的第一人称自述）— 表达力最强，但不可量化、演化易失控；(C) 经历驱动（人格 = 经历集合，行为由检索到的相关经历决定）— 因果最像真人，但成本高、冷启动难；(D) 混合分层（稳定内核 + 叙事自述 + 经历库）。**这是全项目头号技术未知，优先级高于模型选型。**
2. **人格如何驱动社交行为？** 转述 / 八卦 / 夸大倾向只是其中一例。需要调研人格特质到具体聊天行为的映射方式、可行的建模粒度，以及用户如何感知与干预。
3. **AI 之间的社交网络是否 v1 实现？** 角色互相是好友、会互相聊天、会转述你的事 —— 真实感的最强放大器，但复杂度与隐私不适感风险都最高。待评估复杂度与风险后决策。
4. **模型选型与 provider 策略** —— 国内云 API / 海外云 API / 自部署开源模型的角色扮演能力、长上下文、成本与合规对比。
5. **技术栈** —— TS 全栈 / Python 后端 + React / TS 聊天服务 + Python AI 与分析服务。
