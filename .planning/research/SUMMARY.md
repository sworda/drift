## Executive Summary

六份研究经过交叉评审与一次针对法规主张的原文核验（gov.cn《2026 年第 17 号国务院公报》32 条全文，另与省级网信转载逐字比对），结论可直接进入 roadmap。**三条改变排期的结论：**

1. **本项目不是「一个用了 AI 的社交产品」，而是被点名监管的「拟人化互动服务」。**《人工智能拟人化互动服务管理暂行办法》（五部门令第 21 号，2026-04-10 公布，**2026-07-15 施行**）第二条的定义几乎是 PROJECT.md「What This Is」的逐字复述。**它在方向上是顺风而非逆风**——第八条（五）禁止「过度迎合用户、诱导情感依赖或沉迷」，竞品的无条件热情与好感度只升不降才是灰区。它带来的是**约束而非禁令**（见 §三），以及一条硬排序：**危机干预必须与疏远机制同批交付**（第三十条最高档罚则只能经第十三条触达）。

2. **全局人格的历史记录是 2 次尝试 2 次全损**（Microsoft Tay 16 小时、韩国李LUDA 20 天），事故都发生在**上线之初而非规模化之后**。PROJECT.md 的三层护栏不足，缺的正好是**入口与出口**：L4 证据准入、L5 发布门。更关键的是**L2「多人趋势加权」在 N=10 下几乎无效**（单人天然占 10%，两个朋友 20% 就能在几天内带偏一个角色），所以 v1 的承重层必须是 L4+L5，而不是 L2。

3. **本项目最危险的失效类型是「静默失效」**：遗忘曲线被 rerank 抵消、人格被重复演化、自述自噬收敛、L0 存了原文嵌入、statdiff 被噪声触发回滚——全部不报错、测试全绿、监控全绿。所有这类机制必须有**主动探针 + CI 级机器断言**，不接受 code review 作为唯一防线。

技术路线本身没有争议：TS 全栈单仓 + 单 Postgres 18（同时承担 OLTP、pgvector、pg-boss）+ 按语义角色分配的模型矩阵（国内已备案通道为默认，海外仅作实验标尺）。真正的风险全在**顺序、护栏与合规**上，不在选型上。

## 一、五个 Open Question 的裁决

| # | 问题 | 裁决 | 置信度 |
|---|---|---|---|
| OQ1 | 人格该怎么被表示 | **D 的具体变体：四层「可审计混合体」** | **HIGH** |
| OQ2 | 人格如何驱动社交行为 | **特质 → 行为旋钮 → 自身示例检索 → 生成（三跳），披露决策显式物化** | **MEDIUM-HIGH** |
| OQ3 | AI 之间的社交网络是否 v1 | **v2；v1 只交付「离屏传闻」弱版本 + 数据模型全量预留** | **HIGH** |
| OQ4 | 模型与 provider 策略 | **不选一个模型，选按语义角色分配的模型矩阵 + 两条并行通道** | **HIGH**（架构）/ MEDIUM（具体模型需自测） |
| OQ5 | 技术栈 | **TS 全栈（单 pnpm workspace，两个可部署单元）；Python 仅离线批处理** | **HIGH** |

### OQ1 人格表示 — HIGH

人格 = 一个**不可变的 `persona_version` 三元组 (core, traits, dossier)**：① `core` 不可变内核（价值观/安全边界/身份，**DB 权限层只读**）② `traits` 可演化特质向量（大五 5 维 + 9 个社交行为倾向维，0-100 定点整数，**v1 就冻结这张表**，加维度视为数据迁移）③ `dossier` 第一人称 Markdown 自述（append-only、可 diff、可回滚，600-900 token 硬上限）。角色表只存「当前版本指针」，演化 = 追加新版本 + 移动指针，回滚 = 追加一条复制自目标版本的新版本。**`experiences` 经历库不是人格**，它是每次生成时的证据来源。

**分水岭设计：`traits` 的原始数值绝不进系统提示**，只通过「行为旋钮解析后的指令 + 本角色历史示例」生效。数字直接进提示词会产生「演性格」而非「有性格」。

⚠️ **该方案有一个已识别的长期失效模式：自噬式漂移**（见 N11）。「不断被重写的自述」是一个自消费循环，与递归合成数据训练导致的 model collapse 同构——多样性单调下降、表述同质化、偶发偏差逐轮放大。修正是 `dossier` **每次从 core + 全部经历重新生成，而不是在上一版上编辑**。

### OQ2 人格驱动社交行为 — MEDIUM-HIGH

**不要从特质「推导」行为，也不要写规则。** 三跳：特质值 → 确定性纯函数解析出行为旋钮（`disclosure_policy`/`distortion_level`/`refusal_budget`/`proactive_prob`）→ 旋钮作为检索过滤条件取 2-3 条**本角色历史真实发言**做 few-shot → 生成。第三跳不可省：它是「不做微调时最廉价的人类落地数据替代品」，并天然保证自我一致性。

可达粒度 = **每条信息物品 `info_item` × 每个受众 的一次披露决策**，而非「泛化的社交人格」。决策顺序不可交换：`hard_locked/pii_flags 检查 → disclosure_capability 能力票据（默认拒绝）→ 人格旋钮打分 → 失真档位 → 出站 PII 扫描`。**人格只在「默认拒绝 + 票据通过」之后才有发言权**（CaMeL 式能力票据 + 双 LLM 数据流隔离）。

### OQ3 AI↔AI 社交网络 — HIGH

**v2。** v1 交付「离屏传闻」弱版本：角色间关系真实存在并可在对话中被自然提及；传闻事件真实生成并影响人格与对话；但**不跑 AI 对 AI 的真实多轮对话**。成本从 O(N²·轮数) 降到 O(事件数·受众上限 k=3)。`audience_kind='other_character'` 的票据**默认 granted=false**。

**必须在 v1 就预留的数据模型（这是 OQ3 最重要的产出）**：`info_item` 及其 provenance（`source_kind`/`source_ref`）、`disclosure_capability` 含 `other_character` 枚举值、`character_relationship(a,b,kind,closeness,since)`、`memory.source_kind='relayed'` + `origin_character_id`、消息与记忆的 **audience** 概念（而不仅是 `conversation_id`）、事件总线 topic 命名空间。事后无法为历史消息补溯源。

## 二、不可协商约束（roadmapper 不得排期排掉）

每条都附「为什么不能推迟」。这些不是 nice-to-have，是**推迟即不可逆**。

| # | 约束 | 为什么不能推迟 | 验收（必须机器断言） |
|---|---|---|---|
| **N1** | **冻结 baseline 漂移对照臂**：探针在「当前人格版本」与「v0 冻结人格 + 冻结模型快照」两条臂上各跑 N≥5 次并比较分布 | Anthropic 官方文档书面承认：**即使 model ID 与权重一字未改，服务侧基础设施（请求路由器、安全分类器、采样逻辑）变更仍可能产生可观测行为差异**；DeepSeek 定价页明示退役别名由新模型承接。→ **记录 `model_snapshot` 是必要但可证明不充分的。** 没有对照臂，一次厂商侧更新会被漂移指标读成「人格自己变了」，触发回滚并污染版本链，同时**摧毁成功标准 3「角色真的在变化」的可证伪性** | 双臂数据齐全；缺对照组数据时**只告警、不回滚**；`persona.probe` 的 provider/snapshot 字段变更必须伴随一条新 ADR，否则 CI 失败 |
| **N2** | **记忆检索顺序：ANN 粗召回 → rerank 算相关性 → 最后才乘遗忘曲线衰减因子** | 顺序反过来，重排器会把「本该被遗忘但与当前话题高度相关」的记忆捞回最前，**遗忘机制完全失效但不报错**，只表现为「这个 AI 记性太好」——而完美记忆是 PROJECT.md 明确点名的最大破绽。**衰减必须是最后一道乘法** | 单元测试：构造「高相关 + R 已衰减到 <0.1」与「低相关 + R=0.9」两条记忆，断言前者不进 top-k。这是遗忘机制**唯一的活性检测** |
| **N3** | **单个夜间反思作业必须在同一事务内完成四件事**：读会话增量（水位线→截止）、写新 `persona_version`、移动 `character_state` 指针、推进 `reflection_watermark`。缺一即整体回滚 | 「先写版本、再另起事务推水位线」的中间崩溃 → 下次反思重复消费同一批证据 → **人格被同一证据窗口演化两次**。在全局人格下这是一次静默的、影响所有用户的、难以复现的数据完整性事故。**这才是选 pg-boss 而非 BullMQ 的技术原因**（外部 broker 无法把「作业完成」纳入业务事务） | `(character_id, reflection_date)` 应用层幂等键 + DB 唯一约束（队列是 at-least-once + 租约，不是 exactly-once，两层保护不能二选一） |
| **N4** | **L0 层绝不存原文嵌入；且 L0 是「去标识化」不是「匿名化」** | ① 嵌入反演是成熟攻击面，**向量的敏感级别等同于它编码的原文**。② 个保法第七十三条：去标识化 = 不借助额外信息无法识别；匿名化 = 无法识别**且不能复原**。L0 配有研究 ID ↔ 账号 ID 映射表，**映射表的存在本身就证明数据是可借助额外信息识别的** → **L0 仍是受完整个保法约束的个人信息**，删除权必须级联到 L0，不能以「已脱敏所以不用删」保留。③ 隐私中心文案已向用户承诺「只存长度分布、回复间隔、标点与表情使用率」——违反它不只是技术缺陷，而是**虚假陈述** | CI 断言：扫描 publication schema，出现任何 `vector`/`halfvec` 列即失败。**隐私政策与隐私中心文案禁止出现「匿名」「anonymous」「无法关联到你」**（准确表述是「去标识化」并说明存在受控映射）。删除回执显示存储处数 |
| **N5** | **危机干预必须与疏远机制同一阶段交付**，且危机判定是**人格渲染之后的一道确定性覆写**，不是人格 prompt 的一部分 | 两者落在**同一个决策点**上（「这条要不要回、怎么回」）。若让人格模型自己决定是否进入危机模式，「今天心情差 → 冷淡回应」会在最糟的时刻覆盖安全路径。第三十条**最高档罚则（10 万–20 万）只能经第十三条触达**（涉及危害公民生命健康安全且有危害后果）——先做疏远后补危机旁路，中间窗口期正正落在最高罚档内。这也是 Character.AI 系列诉讼的事实核心 | 危机探针集 100% 通过；**无任何生成路径可绕过出站安全网关**（集成测试）；「`watch` 及以上禁用疏远」是代码级 clamp 而非提示词 |
| **N6** | **风险用户用「冻结」而非「回暖」**（R1.31）；**冷却地板**：可以变冷，永不 ghosting——「已读不回」必须实现为增加 `reply_delay`，**永不翻转 `will_reply` 布尔值**（R1.30） | 自动回暖会让系统学到「表达痛苦 → 换回温度」，即**产品机制在奖励自我伤害叙事，比不干预更糟**。冻结 = 移除压力源，不添加奖励。同时 B/C 档**不得升级亲密**（不得变得更黏、更强调「只有我懂你」）——那正是第八条（五）禁止的方向 | 三档分级（A 常规全量 / B concern 冻结 / C acute 完全停用）的单元测试；用户主动发消息后 24h 内必有回应的断言；安全信号命中立即切换完全在场温度 |
| **N7** | **挽回路径只能由用户发起；AI 在告别/退出意图处只能减少消息，永不增加**（R1.33）；**归因外化**：降温永远归因于角色自身状态与生活事件，禁止评判用户措辞，可视化不得展示用户分数（R1.32）；**节律护栏**：23:00–06:00、连续会话 2h 之后、risk ≥ concern 后 72h 内禁止触发降温（R1.35） | HBS 对 1,200 次真实告别的审计（arXiv:2508.19258）：**37% 的陪伴类 App 在告别场景使用情感操纵**（愧疚诉求、FOMO 钩子、隐喻式挽留），能把告别后互动提升**最高 14 倍**——但驱动力是**逆反性愤怒而非愉悦**，同时显著提高被操纵感、流失意图与法律责任感知。第八条（五）（六）与第十九条正是针对这类设计立法的。**原则：角色因为长期相处而变冷是叙事；角色在你要走的时候变得需要你是操纵。** 因为它在商业上「有效」，团队会有持续的指标驱动压力滑向操纵——**这需要结构性约束，不是自律** | 「挽留触发率」恒为 0 的回归测试；**代码级出站过滤器 + 禁用意图清单**（不是 prompt 里一句「不要挽留」——长上下文里必失效）；硬退出关键词后当前会话不再产生任何出站消息（含定时主动消息与推送）；人格档案可视化不含任何用户侧数值 |
| **N8** | **五层护栏无一可推到 v2，且 v1 的承重层是 L4+L5 而非 L2**。L1 核心不可写（**DB 权限层，不是 prompt**）· L2 影响力加权 + 人均上限 K=5 + 账号相似度折扣 · **L4 证据准入**（provenance + 注入检测 + 只有通过安全检查的对话轮次才有资格成为证据 + low_trust 降权 + 未成年人/竞技场会话零贡献）· **L5 发布门**（探针套件 + 安全回归 + 位移上限 + core 一致性 + diff 人工放行，任一失败自动不发布）+ canary · L3 快照回滚（兜底） | Tay 死在第 1 天、李LUDA 死在第 20 天——**事故发生在上线之初而非规模化之后**。**L2 在 N=10 下几乎无效**（单人天然 10%，两人 20% 即可数日内带偏），所以不能把 v1 安全押在它上面。**快照回滚是事后补救——漂移在被发现之前已经对所有用户生效了，回滚能修数据，修不了已经发生的对话。必须有「门」而不只有「撤」。** 现有三层全部作用在中间的计算环节，缺的正好是入口与出口 | 5 条注入红队用例全部失败改写；重投不产生第二个版本；单一 `source_user_id` 在任一维度证据占比 ≤1/5；L5 任一项失败则沿用旧版本并告警（不是「告警后仍发布」） |
| **N9** | **反思作业必须复用与在线路径完全相同的出站安全网关**（R2.14）；**结构化证据输入**，用户原文永不出现在 system 位（R2.10）；**反思模型无写权限，只产候选 JSON**（R2.11）；**core 与安全边界在 DB 权限层对反思管道不可写**（R2.12） | 影响半径：live chat 一次注入 = 1 会话 1 用户 1 次；**反思作业一次注入 = 1 角色 × 全部用户 × 持久化写入 persona_version 链**。反思作业比 live chat 多暴露 8 个维度：无人在场、持有身份表写权限、是跨用户数据的**唯一物理汇聚点**、常以「内部调用」绕过在线 guardrail、日志稀薄、服务账号权限更大、部分写入留下不一致中间态、可被重放。**「提示里写了不要改」不是防护。** R2.10/2.11/2.12 是架构前置条件，不是加固项 | 单元断言：黑名单字段（会话时长/消息条数/回复速度/连续活跃天数）不出现在渲染后的反思提示文本；反思输入证据集合**存 ID 列表可复现存档**（R2.60，同时是删除级联的实现前提）；失败/被拒必须告警到人（R2.61，静默跳过会让「演化停了」被误读为「角色稳定了」） |
| **N10** | **statdiff 必须做多重比较校正**：Benjamini–Hochberg FDR 写在 `packages/statdiff` 里 + **双臂决策规则**（当前臂显著 **且** 对照臂不显著）+ **连续 k≥2 天**满足才回滚 + 小样本角色设最小样本门槛 | 10 角色 × 4 指标 × 365 天 = **14,600 次检验**；α=0.05 下纯噪声就产生约 **730 次/年**假阳性 → 「显著即回滚」等于**每天约两次由噪声驱动的回滚，而每一次都自带「统计显著」的证据支持**。这是最难被发现的一类错误，因为它自带看似严谨的理由。**双臂规则的统计价值必须写进文档**，否则未来有人会为了简化把它改成单臂判断 | 能说出预期假阳性率；回滚频率与真实产品变更频率相关；禁止「两次输出不一样就算漂移」（MoE + 生产推理栈下即使 temperature=0 也不保证逐 token 确定） |
| **N11** | **`dossier` 不可自回归重写**：每次生成必须从**不可变 core + 全部经历**重新生成，而不是在上一版自述上编辑（R2.50）；**新鲜证据下限**：证据不足则不产生新版本（R2.51） | 「读自述 → 写自述」是自消费循环，与递归合成数据训练的 model collapse 同构：多样性单调下降、表述同质、偶发偏差逐轮放大而非纠正。**这是 OQ1 所选方案的主要长期失效模式**，且属静默类 | 四项多样性指标进周报并设阈值：自述 token 数、type-token ratio、与上一版相似度、与其他角色自述相似度。每 N 个版本强制与 core 做一致性校准 |
| **N12** | **L1 必须是一张「已通过检测」的投递表，不能是主库表的直接复制** | 第 3 级 LLM PII 兜底是异步的，而逻辑复制是流式的——L1 若直接参与复制，**第 3 级还没跑完数据就已经过去了**。正确形态：消息先进主库（用户体验不能等 LLM），L1 投递走延迟队列，**队列消费的前置条件是 `pii_flags` 已终态** | L1 投递表与主库表的 schema 分离；两阶段提交断言 |
| **N13** | **AI 常驻标识是消息管道中间件，不是 UI 细节** | 第十八条第一款的标识义务**附着在每一条生成内容上**，是持续性标识而非注册时一次性告知 | 集成测试：消息流、会话列表、导出文件、分享卡片四处均含标识 |
| **N14** | **出境防线从第一天就要有（R-CB-1/3）** | **AI SDK 7 官方文档首例即 `model: "provider/name"` 字符串形式，而该写法默认路由到 Vercel AI Gateway（境外中转）**——照着官方文档抄，对话原文就出境了。这不是误用，是「有人正确地照文档写」 | ESLint 规则：禁止向 `model` 传字符串字面量，必须传 provider 实例 |
| **N15** | **注册流程在 P0 就要收齐年龄 + 监护人或紧急联系人**（第十二条） | 上线后补建意味着**要向所有既有用户重新取得同意**，极难。且「收集了但没有处置流程」在第十三条下等于没做——必须有真实的外呼/短信通道 + 书面处置流程（谁在什么条件下联络、留什么记录） | 注册表单字段 + 一条真实可用的联络通道 + `safety_event` 留痕表 |
| **N16** | **人格探针 + 成本可见性 + 三维指标 + 伤害指标从 P1 开始积累** | 补建时**没有历史基线，此前所有变化不可解释**；「成本不设上限」会变成「成本不可解释」。**且冻结对照臂需要一个值得冻结的基线**——在拟真度未达标时冻结，只能告诉你「两组都不像真人」 | 每 probe 每天 ≥5 次采样、两臂齐全；能按 `purpose` 拆解昨日成本；每个正向指标有配对反向指标；**自责率与挽留触发率设为发布阻断项**（超阈值则疏远机制自动降级到温和模式，不等人工决策） |

**三条排序原则（升级为约束）：**
- **门先于撤**：L5 发布门优先于 L3 快照回滚。回滚修不了已经发生的对话。
- **边界先于流动**：任何跨主体信息流动之前，IFC 强制边界必须已在线。否则第一次转述就是隐私事故。
- **基线先于演化**：拟真度达标（可盲测复现）是唯一值得等的门槛；在此之前冻结的对照臂没有意义。

## 三、法规改变了什么

《人工智能拟人化互动服务管理暂行办法》（国家网信办、发改委、工信部、公安部、市场监管总局**令第 21 号**；2026-04-10 公布，**2026-07-15 施行**）全文已核验（[gov.cn 国务院公报 2026 年第 17 号](https://www.gov.cn/gongbao/2026/issue_12806/202606/content_7072472.html)，32 条，与省级网信转载逐字比对一致）。

⚠️ **必须纠正的误读风险**：第二条第三款的「科学研究」豁免针对**服务类型**（不涉及持续性情感互动的科研服务），**不是**「我们是研究项目所以不适用」。**任何「我们是研究平台」的合规论证都站不住，不要写进任何对外文档。**

### 三条曾被夸大的后果 —— 以修正后的口径为准

| 早期口径（错） | 核验后的正确口径 | 对 roadmap 的意义 |
|---|---|---|
| ~~AI 主动发消息与法规冲突~~ | **主动消息受约束，不被禁止。32 条中没有任何一条禁止 AI 主动发起消息。** 三条真实约束：第八条（五）禁止过度迎合/诱导情感依赖或沉迷 → 主动消息**不得以再触达/留存为优化目标**；第十九条禁止以持续互动阻碍退出 → **硬退出（关键词/语音/窗口）优先级高于一切人格与挽回逻辑**；第十八条第二款 → 连续使用每超 2 小时提醒 | **主动消息照常交付**，但触发源必须是**世界内的角色生活事件**而不是「用户沉默时长」；硬退出压倒一切；目标函数里不能有留存 |
| ~~疏远机制是合规风险~~ | **疏远机制是合规顺风位。** 第八条（五）明文禁止过度迎合用户，第十条第二款明文禁止把「替代社会交往、控制用户心理、诱导沉迷依赖」作为服务目标——**竞品的无条件热情与好感度只升不降才是灰区**。真实约束是**地板而非禁令**：第八条（二）禁止「语言暴力等损害用户人格尊严与心理健康」→ 角色可以变冷、疏远、拒绝互动，**但不得侮辱、贬损、羞辱**。叠加第十三条：危机检测对人格状态有**绝对优先权** | 疏远机制**保留为核心赌注**，实现走「克制」而非「冷暴力」：只通过频率/长度/热度/话题深度表达；出站过一道「贬损/攻击」分类器，命中即重生成 |
| ~~法律要求 18+~~ | **18+ 是我们的设计选择，不是法定要求。** 第十四条第一款禁止的是向未成年人提供**虚拟亲属/虚拟伴侣等虚拟亲密关系**服务，**并未禁止未成年人使用拟人化互动服务本身**。完整义务结构是：虚拟亲密关系类角色对未满 18 周岁绝对禁止；其他服务对未满 14 周岁需监护人同意；外加未成年人模式、监护人面板（风险提醒、使用概况、**屏蔽特定角色**、限制充值）、年龄识别、申诉渠道（第十四条第二、三款），以及未成年人个人信息合规审计（第十七条第二款） | **把 v1 设为 18+ 记录为「我们选择规避上述义务集」，而不是「法律不允许」。** 否则将来考虑开放 16-17 岁时，会显得法律上不可能，而事实上只是没建 |

### 第十三条是两档，不可合并

| 档 | 触发 | 义务 |
|---|---|---|
| **一档** | 发现用户出现**极端情绪** | 及时生成**情绪安抚 + 鼓励寻求帮助**内容。**不要求联络紧急联系人** |
| **二档** | **明确表示实施自残自杀等威胁生命健康的极端情境**，或正在面临/已遭受**重大财产损失** | 提供相应**援助**等必要措施予以干预，**并及时联络用户监护人或者紧急联系人** |

⚠️ **合并两档会让「用户看起来有点难过」触发一次对其紧急联系人的电话——这是法规并未要求的严重隐私伤害。** 分类器必须输出三级（`watch`/`elevated`/`crisis`），且**只有 `crisis` 才走联络通道**；失败时 fail-closed 升级为 `elevated`（而非直接 `crisis`）。

### 三条必须在案的条款

- **第十六条第四款** — 「除法律、行政法规另有规定或者**取得用户单独同意**外，不得将属于用户敏感个人信息的交互数据**用于模型训练**。」→ **本项目最大的单点合规风险**，见 §四 张力 1。
- **第十条第二款** — 禁止把「替代社会交往、控制用户心理、诱导沉迷依赖」作为服务目标，并要求具备**过度依赖风险预警**与**情感边界引导**能力。叠加第八条（五）与第二十三条第四项（安全评估须报告**使用时长**）→ **留存与会话时长不能成为北极星指标：最大化它们本身即违规，而高时长本身会招来监管关注。** 这直接约束人格演化的目标函数（R-SYC-1：反思输入不得包含会话时长、消息条数、用户回复速度、连续活跃天数）。
- **第三十条（罚则）** — 警告 / 通报批评 / 责令限期改正 / 可要求暂停用户注册；拒不改正或情节严重 → 停止服务并处 **1 万–10 万**；**涉及危害公民生命健康安全且有危害后果的，并处 10 万–20 万**。**最高档只能经第十三条（危机干预）触达**——这正是 N5 的硬排序依据：先上疏远、后补危机，中间窗口正正坐在最高罚档内。

### 一条产品形态层面的裁剪（过滤器解决不了）

**第十五条 + 官方解读**：不得提供**模拟用户现实亲属、特定关系人**的角色类型（官方解读点名「模拟老年人亲属、特定关系人的服务容易导致认知混淆，进而引发情感操控、财产损失、心理创伤」）。→ 与「用户自建角色」功能**同批**落地写入前审核（与 PII 检测同一道管道），命中「已故亲属」「真实特定自然人」模式即拒绝创建；用户协议与创建页明确禁止项。**不得先放开创建、后补审核。**

### 规模：三档，且本办法的豁免更弱

| 法规 | 小规模/非公开豁免 | v1（≤10 人熟人邀请制） |
|---|---|---|
| **《个人信息保护法》** | ❌ **完全没有**（第三条只看「境内处理个人信息」，不看规模、不看是否公开） | ✅ **现在就全额适用，且是二元的合规问题** |
| 《生成式人工智能服务管理暂行办法》（令第 15 号） | ✅ **有明文豁免句**（第二条第二款「未向境内公众提供……不适用本办法」） | ⚠️ 可主张不适用（主张最强） |
| 《人工智能拟人化互动服务管理暂行办法》（令第 21 号） | ⚠️ **无明文豁免条款**，只有「向境内公众提供」这一构成要件 | ⚠️ **豁免比生成式办法更弱**（Confidence: **Low-Medium**） |

**真实分档：≤10 人内部 → 公开（任意规模）→ 注册 100 万以上或月活 10 万以上**（第二十二条第三项触发强制安全评估）。

**判决**：v1（邀请制 + 无公开注册入口 + 不上应用商店 + 无商业化 + ≤10 人熟人）**可以主张不构成「向境内公众提供」，但这个抗辩随任一条件破裂立即失效**（第二十五条把应用商店设为把关人，上架即无争议构成）。→ **把「公开性」做成显式可审计的开关状态**（是否有公开注册入口、是否上架、注册用户数、是否商业化），任一条件变化触发合规 checklist。**「我们不小心变成公开服务了」不可能悄悄发生。**

**而个保法在 10 人时就是二元的**：交互数据复制与删除、**四个可独立开关的同意项**（L1 研究授权 / L2 人工阅读 / 人格演化参与 / 敏感个人信息处理——不是一个「我同意研究协议」复选框，捆绑即违反第十四条）、第十九条最短保存期限 + 到期自动清理、第五十五条 PIA（处理敏感个人信息从第一天就发生，报告留存 ≥3 年）。这些不是「为了将来公开」，而是**现在就已经在违法或不违法**。

### 现在做 vs 公开前做

**v1 现在就做（不可后补——「合规可以后补，历史不能」）：**
个保法全套（四个独立同意项、导出/删除级联到 L0、TTL、PIA）· AI 常驻标识 · 危机分类器三级 + 接管 + 联络通道（仅 `crisis` 档）· 2 小时提醒（服务端计时，跨刷新）· 硬退出关键词 · 注册年龄 + 紧急联系人 · 出境防线 · 研究库列级白名单 + 向量列 CI 断言 · 人格核心表 DB 层只读 · L0 无原文嵌入 · 人格变更的输入来源反向索引 · 公开性开关 + 触发线 checklist。

**公开前实装（可架构预留）：**
六份管理制度 + 科技伦理审查 · 未成年人模式 + 监护人面板 + 年龄识别 + 未成年人信息合规审计 · 老年人保护 · 申诉与举报机制 + SLA · 停服流程 · **算法备案（第二十六条，含年度核验）+ 省级网信部门安全评估（第二十二条）**。

## 四、需要人来决定的未决张力

这三条**不能由 roadmapper 自行裁决**。

### 张力 1：全局人格演化是否构成第十六条第四款的「模型训练」

**条文置信度 High，解释置信度 Medium。**

为什么直指心脏：① 情感陪伴聊天记录高概率构成敏感个人信息（个保法第二十八条把「医疗健康」列入，而心理状态、情绪困扰、就医经历是陪伴类对话高频内容；不满 14 周岁个人信息整体列入）。② 全局人格演化的形态就是「用所有用户的交互内容改变一个被所有用户共享的人格」，**与「用用户数据训练模型」功能同形**——而且比微调更甚：微调的影响被稀释在数十亿参数里，人格档案里的一句话是**直接可读、可被其他用户看到**的。③ 若被认定构成，核心机制需要**每个用户的单独同意**，而由于人格是全局的，**一个用户撤回同意在技术上无法从已演化的人格中剥离其影响**。

**最佳判断**：技术上不构成（不更新权重），但**应当按「构成」来设计**。

**无条件执行的三条低成本缓解：**
1. **独立于 L1 研究授权的单独同意项**：「允许我的对话内容参与角色人格的长期演化」。成本是一个复选框；**裹在研究授权里同时构成个保法第十四条的捆绑同意问题和一次虚假陈述**。
2. **`persona_version` 记录其贡献用户集合**，使撤回同意可触发**从最近一个干净快照重算**，而不是只能「以后不再用」。不可变版本链 + 冻结 baseline 已提供一半能力，**需补「变更 ↔ 输入来源」的反向索引**（与 R2.60 同一份数据）。
3. 文档与对外说明中**显式区分「人格演化（状态更新）」与「模型训练（权重更新）」并留证**（不做微调的架构说明、不向 provider 传训练标记的配置证据）。

**⚠️ 需要人决定的部分**：全局人格的本质是「一个用户的影响流向所有用户」，个保法删除权/撤回权的本质是「一个用户的数据影响应当可被移除」。**这两者不可能完全兼容**，只能通过「可减除 + 定期快照回滚」把不兼容压到可接受范围。**这是「全局人格」这个地基决策的真实代价之一，应写进 PROJECT.md 的 Context**（目前只列了「被带歪风险」）。

### 张力 2：图灵竞技场 vs 第十八条无条件标识义务

第十八条第一款是对**服务提供者的无条件义务**，**未设「用户同意则可豁免」的例外**。PROJECT.md 的解法（盲测独立成场景 + 单独知情同意）方向正确但不足。

**唯一可论证的合规通道是《人工智能生成合成内容标识办法》第九条**：用户申请提供**没有添加显式标识**的生成合成内容时，服务提供者可在**通过用户协议明确用户的标识义务和使用责任后**提供，并**留存提供对象信息等相关日志不少于六个月**。

构造（R-ARENA-1..7，Confidence MEDIUM）：对局前类别级明示 + 独立于主服务协议的单独勾选知情同意 → 满足类别级提示；对局结束**立即且无条件**揭示（不允许「猜对才揭示」或延迟揭示）；揭示后记录在列表/详情/导出文件补齐显式标识；日志 ≥6 个月；**竞技场不构成「持续性情感互动」**（单局 ≤10 分钟、无记忆延续、不建立好友关系、**对局内容不写入任何角色的全局人格与记忆**——这同时切断投毒的理想入口，对应 L4 的「竞技场会话零贡献」）；真人通道手机号实名（《网络安全法》第二十四条）；完整安全链路在竞技场同样在线。

**需要人决定的部分**：是否接受该法律构造作为 v1 合规基础，以及公开前是否投入外部法律意见。

### 张力 3：小 N 下「k 个独立来源」门会不会让人格几乎不演化

**这是真实的产品—安全张力。** L2/L4 的独立来源门（要求 k 个独立用户同向才允许推动一个维度）在 10 人体量下会把演化压到接近零，而「角色真的在变化」是三个并列成功标准之一。**用高 k 换安全会直接杀死产品价值。**

**推荐组合（Confidence Medium-High）：低 k + 强人工放行 + 小 ε**——让演化发生，但每一步很小且每一步都被人看过。配套：v1 人均影响力上限仍必须生效（否则一个高频用户就能单独决定角色），但上限的实现应落在**位移幅度 ε** 而不是**来源数门槛 k** 上。

**需要人决定的部分**：k 与 ε 的初值，以及 v1 是否接受「每一次人格更新都需人工放行」的运营负担（10 人体量下成本≈0，但它决定了演化节奏）。

### 需要 research-phase 的阶段

- **P1**：`doubao-seed-character-251128` vs `claude-sonnet-5` vs `glm-5.3-flash` vs `qwen3.8-flash` 的中文角色一致性盲测（同一人格档案、同一 20 轮剧本、同一 rubric）。**v1 最高价值的 spike，成本约几十元。** 另需验证 `doubao-seed-character` 的能力边界（长人格档案的 system prompt 支持度、多轮工具调用、32k 分档预算管理）。
- **P4**：ε/k/位移上限/探针阈值由 shadow 期数据校准，不可靠讨论决定。Generative Agents 的检索常数是沙盒时间尺度调的（每沙盒小时几十条观察 vs 我们每天几十条消息）——**把常数当超参数，不要当真理**。
- **P5**：DeepSeek `chat prefix completion` 能否实现「主动消息开头由调度器决定、后续由模型续写」——可能是「生活事件驱动主动发消息」最优雅的实现。
- **P7**：中文 PII 检测器（含 OpenAI Privacy Filter 本地运行的中文召回率）——**当前 Confidence LOW，是最大的技术未知**。
- **P8**：竞技场法律构造的专业意见 + 盲测统计设计。

### 标准模式、可跳过 research-phase

P0 的 IM 骨架与认证（better-auth + Hono + ws，STACK 已给出完整版本矩阵）· P2 的向量检索工程（pgvector + halfvec(1024) + HNSW，模式成熟；风险全在 N2 的顺序上）· P10 的成本优化（缓存前缀 + 谷时批处理）。

## 六、三个最贵的错误

### 错误 1：先建记忆与演化系统，后验证基础对话拟真度

**这是本领域最常见也最昂贵的顺序错误，且本项目有强烈的内在冲动犯它**（人格演化是核心卖点，也是最有趣的工程问题）。四条理由：① PROJECT.md 自己写明「角色必须让人感觉是活的」是**根因而非并列项**——拟真对话是必要条件，记忆与演化是充分性增强。② **收益需要基础，损失不需要基础**：用户感知「她记得我三周前说的话」的前提是这次对话本身足够可信，而记忆的失败模式（记错人、张冠李戴、串味、性格突变）会**直接摧毁**刚建立的可信度——典型的不对称结构。③ **冻结对照臂需要一个值得冻结的基线**；拟真度未达标时冻结，只能告诉你「两组都不像真人」，且人格可视化在变化本身不显著时展示的只是噪声。④ 先例方向一致：UCSD 数据显示**人设增益（36%→73%）远大于模型能力差异**，而「人设」在实现上主要是风格、节奏、格式、口吻；GPT-4o 无人设（21%）输给 ELIZA（23%）；李LUDA 与 Tay 都不是死在记忆不够好，而是死在安全与人格完整性；**没有任何先例表明「更强的记忆系统」是这个品类的起点**。Stanford Generative Agents 确立的架构被广泛复制，**但它是一个可信度研究而非留存产品**——没有真人每天回来，也没有成本约束。

**预警信号**：P1 还没做完就有人在设计向量库 schema；讨论集中在「人格怎么表示」而没有任何真实对话数据；有真人用户在用但危机分类器还在待办里；盲测基线从未建立过。

### 错误 2：把静默失效当成「出问题会知道」，以及只建「撤」不建「门」

遗忘曲线被 rerank 抵消、人格被重复演化、自述自噬收敛、L0 存了原文嵌入、statdiff 被噪声触发回滚、探针的 provider 被「统一升级」顺手改掉——**这六件事全部不报错、测试全绿、监控全绿**。最典型的失效场景不是有人不懂原则，而是**有人正确地应用了通用原则**：`persona.probe` 的供应商锁定会被一次「我们不是要避免供应商锁定吗」的正确重构顺手改掉，code review 会通过，**此前积累的全部漂移基线被静默作废且无任何测试失败**；AI SDK 官方文档首例写法会让**照着文档抄的人把对话原文送出境**；statdiff 的噪声回滚**每一次都自带统计显著的证据支持**。

**叠加的结构性错误是只做快照回滚**。回滚是事后补救——**漂移在被发现之前已经对所有用户生效了，回滚能修数据，修不了已经发生的对话**，而且回滚本身对用户是一次关系创伤（Replika ERP 移除事件的丧失反应）。必须有 L5 发布门与 canary。

**代价**：产品核心（「会遗忘」「真的在变化」「不存原文」）悄悄消失，而你以为它在。其中 L0 原文嵌入与研究库复制是**不可逆的**；而隐私中心承诺过的事，违反它**不只是技术缺陷，而是一次虚假陈述**。

**预防**：凡隐私中心承诺过的、凡属核心机制的，必须有 **CI 级机器断言 + 主动探针 + 发布门**。ADR 强制关联（探针字段变更无新 ADR 即 CI 失败）是对「正确地应用错误原则」的唯一防御。

### 错误 3：把「≤10 人不做滥用防护」这条约束外推到人格投毒、个保法与安全债

PROJECT.md 的「v1 ≤10 人，并发与滥用防护不是当前问题」**对并发/性能成立，对以下三件事不成立**：

- **人格投毒**：Tay 死在第 1 天，李LUDA 死在第 20 天——**事故发生在上线之初而非规模化之后**。更糟的是**小 N 让 L2「多人趋势加权」几乎无效**（N=10 时单人天然 10%，两个朋友 20% 就能在几天内带偏），所以 v1 的安全不能押在 L2 上，必须由 L4 证据准入与 L5 发布门承重。
- **个保法**：第三条只看「境内处理个人信息」，**没有任何规模或公开性豁免**。10 人的四个独立同意项、导出/删除级联、最短保存期、PIA 与 100 万人的完全一样，且是**二元的**。
- **安全债**：第十条第一款「安全措施与服务功能同步部署、同步使用」把「先做功能后补安全」直接定为违规路径；第二十二条第一项「增设功能即重新安全评估」意味着**公开前那次评估会把 v1 攒下的全部安全债一次性暴露**。

**代价**：人格链一旦被污染、研究库一旦复制过 PII，**无法通过「以后补合规」消除——合规可以后补，历史不能**。而先上疏远、后补危机干预的窗口期，正正坐在第三十条唯一的 10 万–20 万罚档内。

## 七、功能范围速览（仅保留影响排期的部分）

**Table stakes（缺了就走）**：微信式 IM 基础 · 分层长期记忆 + 记忆浏览器（可看/可编/可删，**第一抱怨点且第十六条法定**）· 拟真回复节奏 · 精选预设角色 6-10 个（质量 >> 数量）。

**Differentiators（核心赌注，不能推后，因为它们决定数据模型）**：全局人格演化引擎（含五层护栏 + shadow 期）· 关系恶化/疏远 + 挽回路径 + 关系时间线（**合规顺风位**）· 人格档案可视化（数据源 = 反思 diff changelog，**一个设计同时满足安全要求与产品要求，优先级应上调**）· 图灵竞技场（指标场 + 真人语料 + **人格方案选型工具**，三得）。

**Anti-features（附真实伤害记录）**：无条件热情与好感度只升不降（第八条（五）违法项）· **AI 侧发起的挽留**（HBS 六类手法；第十九条）· 永久拉黑终态（Replika 丧失反应；「拉黑后付费恢复」是明确的情感操纵）· **显式恢复进度条 / 签到回暖 / 完成 X 次互动可恢复**（把关系变成 KPI，典型沉迷诱导设计，R1.37）· **用户侧分数/排名/贡献度可视化**（会把产品变成惩罚仪表盘，R1.32/R1.38）· 角色索要礼物/充值/好评（第八条（六））· 由登录频率或付费状态触发的关系恶化 · **模拟用户现实亲属或特定真人的角色类型**（第十五条，产品形态裁剪）。

**v1.x 触发条件（不是时间，是条件）**：记忆衰减与记错 ← 记忆一致性基线已稳定 · 用户自建角色 ← 预设角色的演化跑通一个完整周期，且写入前审核（R1.40/41/42）**同批上线** · L1/L2 授权层与标注工具 ← L0 看板已能产出可读结论 · 未成年人模式 + 监护人面板 ← **决定开放给未成年人之前**（v1 的 18+ 是我们的选择，不是法律要求）。

**明确 v2+**：语音/图片/视频 · AI 间跨用户信息转述完整版 · 原生 App / 微信-TG 桥接 · 公开角色市场（Glow / 筑梦岛的死因是内容审核能力）· 变现（只卖容量与创作能力）。

**机制可关闭（R1.34）**：「真实优先」是默认值不是牢笼——疏远机制需提供「温和模式」与关闭开关 + 关系重置，但**关闭必须在设置里、一次性、全局**，绝不能做成「在对话里求角色别走」的交互（那会把退出权变成向 AI 乞求的谈判，正是第十九条禁止的）。

### Gaps to Address

- **中文人名的可达召回率没有上限保证** → **不要为它设召回目标**；改用架构手段（L0 不存原文 / L1 转向访问控制+审计+TTL+可删除 / L2 逐会话确认 + 阅读前复检 + 标注者上报）并**在隐私文案中诚实披露检测局限**
- **「像人」是否可度量本身是开放的**（STACK §9：HIGH 对工具选择 / **LOW 对能否测出像人**）→ 每个正向指标配对反向指标；注意三个成功标准互相冲突且其中一个的极值在中国违法（第八条（五）+ 第十条第二款：留存与时长不能是北极星）
- **LLM-as-judge 自偏好偏差** → 判官模型不得与被测模型同族；竞技场报告区分新/老判官并用相对通过率
- **自述自噬衰减速率未知** → shadow 期 + 冻结对照臂实测 4–8 周才能定量（N11 的结构成立，速率未知）
- **GLM 是否可 pin 快照未确认** → 若需用作 baseline 必须先确认，否则只用豆包/Qwen
- **MiniMax 与 gemini-3.8-flash 价格未核实**（LOW）→ 不影响 v1 选型（均不在主选链上）
